# 数据迁移指南

## 概述

本项目经历了两次加密方案：
- **v1（旧版）**：单字节 XOR 加密（密钥 `0x5A`）
- **v2（新版）**：XTEA-CBC 块加密（128位密钥，32轮，PKCS7 填充）

如果从旧版升级，需要将旧版数据转换为新版格式。系统提供两种升级方式。

## 方式一：自动升级（推荐）

**无需任何手动操作。** 主程序在读取数据文件时会自动检测格式：

1. 读取文件首字节
2. 如果首字节 != `0x02`（旧版 XOR 格式）
3. 用旧版 XOR 解密还原明文
4. 解析数据
5. **自动用新版 XTEA-CBC 重新加密并写回文件**

涉及的代码位置：
- `file_io.cpp` 的 `loadUsers()` — 加载用户列表时自动升级
- `file_io.cpp` 的 `loadPasswords()` — 加载密码数据时自动升级

### 操作步骤

```bash
# 1. 编译新版本
make main

# 2. 直接运行主程序
password_manager.exe

# 3. 登录原有账号
# 数据会在登录时自动升级，无需额外操作
```

> 自动升级是渐进式的：只有被读取的文件才会被升级。如果某个用户一直不登录，其数据文件保持旧格式，直到下次被读取。

## 方式二：手动转换工具

使用独立的 `convert.exe` 工具批量转换所有数据文件：

### 操作步骤

```bash
# 1. 编译转换工具
make convert

# 2. 运行转换工具
convert.exe

# 或指定数据目录
convert.exe D:\my\data\
```

### 转换工具流程

```
1. 扫描 data/ 目录下所有 .dat 文件
2. 对每个文件：
   ├── 读取文件内容
   ├── 检查首字节是否为 0x02
   │     ├── 是 → 跳过（已是新版格式）
   │     └── 否 → 继续转换
   ├── 旧版 XOR 解密 → 明文
   ├── 新版 XTEA-CBC 加密 → 新密文
   ├── 回读验证：用 decryptData() 解密新密文，与明文比对
   │     └── 不一致 → 跳过此文件，报告错误
   ├── 创建 .bak 备份文件
   └── 写入新格式数据
3. 输出统计：成功/跳过/失败
```

### 安全保障

- **备份**：转换前自动创建 `.dat.bak` 备份文件
- **回读验证**：加密后立即用主程序同一套 `decryptData()` 解密验证
- **共享代码**：转换工具直接链接 `crypto.cpp`，与主程序使用完全相同的加密实现

## 故障恢复

### 场景：转换后无法登录

如果使用旧版转换工具（独立实现加密算法）转换后无法登录：

### 恢复步骤

1. **恢复备份**：
   ```
   进入 data/ 目录
   将 所有 .dat.bak 文件重命名去掉 .bak（覆盖坏的 .dat）
   例: users.dat.bak → users.dat
   ```

2. **如果没有 .bak 备份**：
   - 主程序的 `decryptData()` 支持向后兼容
   - 直接运行新版 `password_manager.exe`，旧格式数据会自动读取并升级

3. **运行诊断测试**：
   ```bash
   make runtest
   ```
   确认本机加密算法实现正确（40 项全通过）

4. **重新登录**：
   ```bash
   password_manager.exe
   ```
   使用原有账号密码登录

### 验证转换是否成功

运行诊断测试程序：

```bash
crypto_test.exe
```

它会执行 40 项测试，包括：
- 旧版 XOR 往返
- 新版 XTEA-CBC 3次往返 + IV 随机化
- 0~17 字节 PKCS7 填充边界
- 中文支持
- 模拟完整转换流程（旧XOR → 转换 → 新版读回 + 用户数据解析）

全部通过则说明加密实现正确。

## 注意事项

1. **不要混用不同版本的 convert 工具**：旧版 convert 独立实现加密算法，可能与主程序不一致。新版 convert 直接链接 `crypto.cpp`，保证一致。

2. **转换前备份**：虽然转换工具会自动创建 `.bak`，但建议额外手动备份整个 `data/` 目录。

3. **转换后不要删除 .bak**：确认主程序能正常登录后再删除备份文件。

4. **密钥变更后无法解密旧数据**：如果修改了 `types.h` 中的 `XTEA_KEY`，已有的新版格式数据将无法解密。需要先用旧密钥编译的程序解密数据，再用新密钥编译的程序重新加密。
