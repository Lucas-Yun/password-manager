# 数据格式说明

## 文件结构

程序运行时在程序同级目录创建 `data/` 文件夹，存储所有加密数据：

```
data/
├── users.dat          # 用户列表（用户名:密码）
├── Admin.dat          # 管理员的密码数据（通常为空）
├── zhangsan.dat       # 用户 zhangsan 的密码数据
├── lisi.dat           # 用户 lisi 的密码数据
└── ...                # 每个用户一个 .dat 文件
```

## users.dat 格式

### 明文格式

解密后的明文为多行文本，每行一个用户：

```
用户名:密码\n
用户名:密码\n
...
```

示例：

```
Admin:admin_root
zhangsan:pass123
lisi:mima456
```

### 字段说明

| 字段 | 分隔符 | 说明 |
|------|--------|------|
| 用户名 | `:` | 唯一标识，不能包含冒号 |
| 密码 | 换行符 | 登录密码，不能包含换行符 |

### 加密后格式

```
[0x02] [IV(8字节)] [XTEA-CBC密文]
```

整个明文字符串经 `encryptData()` 加密后写入文件。

## 用户数据文件（用户名.dat）格式

### 明文格式

解密后的明文为多行文本，每行一个平台：

```
平台名:账号1,账号2,账号3:密码\t备注\t创建时间\n
平台名:账号1:密码\t备注\t创建时间\n
...
```

> 使用 `\t`（制表符）作为密码与备注、备注与创建时间之间的分隔符。备注和创建时间为可选字段，无内容时为空字符串，但 `\t` 分隔符仍会写入（保证格式一致）。

示例：

```
GitHub:zhangsan@outlook.com,zhangsan001:G@HubPwd123	主力开发账号	2026-08-06 14:30:25
Gmail:zhangsan@gmail.com:Gm@il_Secret			2026-08-05 09:12:03
Steam:zhangsan_steam,zs_games:St34m_Pwd	游戏账号	2026-08-04 18:45:50
```

> 上例中 Gmail 一行备注为空，因此密码后直接是 `\t` 接空的备注再 `\t` 接创建时间。

### 字段说明

| 字段 | 分隔符 | 说明 |
|------|--------|------|
| 平台名 | `:` | 唯一标识，不能包含冒号 |
| 账号列表 | `,` 分隔多个账号，两端用 `:` 包围 | 多个账号用逗号分隔 |
| 密码 | `\t` | 该平台的密码，不能包含制表符和换行符 |
| 备注 | `\t` | 可选，可为空，不能包含制表符和换行符 |
| 创建时间 | 换行符 | 格式 `YYYY-MM-DD HH:MM:SS`，添加时自动记录 |

### 解析逻辑

```
每行: 平台名 : 账号1,账号2,... : 密码 \t 备注 \t 创建时间
       ↑         ↑                ↑      ↑       ↑
    firstColon  secondColon    密码    tab1    tab2/行尾
```

1. 找到第一个 `:` → 左侧为平台名
2. 在剩余部分找到第二个 `:` → 中间为账号列表（逗号分隔）
3. 第二个 `:` 右侧为 `密码 \t 备注 \t 创建时间`：
   - 找第一个 `\t` → 左侧为密码
   - 在剩余部分找第二个 `\t` → 中间为备注，右侧为创建时间
   - 若没有第二个 `\t` → 剩余全部为备注（无创建时间）

### 向后兼容（旧格式）

旧版本数据行格式为 `平台名:账号列表:密码`（不含 `\t` 字段）。读取时：

- 若密码部分不含 `\t`：整个部分作为密码，备注和创建时间为空
- 旧格式数据读取后会以新格式（带 `\t`）重新写入，实现自动升级

### 数据结构

对应 C++ 结构体（定义在 `types.h`）：

```cpp
struct PlatformInfo {
    std::vector<std::string> accounts;  // 账号列表（可多个）
    std::string password;               // 密码（仅一个）
    std::string note;                   // 备注（可选）
    std::string createTime;             // 创建时间（YYYY-MM-DD HH:MM:SS）
};
```

存储时使用 `std::map<std::string, PlatformInfo>`，键为平台名。

## 加密文件二进制结构

所有 `.dat` 文件都使用相同的加密格式：

```
偏移    大小        内容            说明
0x00    1 字节      0x02           版本标识（CRYPTO_VERSION）
0x01    8 字节      随机值          IV（初始化向量）
0x09    N*8 字节    密文            XTEA-CBC 加密数据（PKCS7 填充）
```

### 版本标识

| 值 | 含义 |
|----|------|
| `0x02` | 新版 XTEA-CBC 加密 |
| 其他 | 旧版 XOR 加密（向后兼容） |

### 如何判断文件格式

检查文件首字节：

```
首字节 == 0x02 → 新版格式
首字节 != 0x02 → 旧版格式（XOR）
```

`file_io.cpp` 中的 `isLegacyFormat()` 函数执行此判断。

## 数据隔离机制

每个用户的数据存储在独立的 `用户名.dat` 文件中。程序加载时只读取当前登录用户对应的文件：

```cpp
// 只加载当前用户的数据
map<string, PlatformInfo> loadPasswords(const string& username) {
    string filepath = DATA_DIR + username + ".dat";
    // ...
}
```

- 用户 A 登录时只读取 `data/A.dat`
- 用户 B 登录时只读取 `data/B.dat`
- 管理员也无法读取其他用户的 `.dat` 文件内容

## 文件创建时机

| 文件 | 创建时机 |
|------|---------|
| `data/` 目录 | 程序启动时 `createDirectory(DATA_DIR)` |
| `users.dat` | 首次保存用户时（首次运行自动创建 Admin） |
| `用户名.dat` | 用户注册时创建空文件 |
| `用户名.dat.bak` | 转换工具运行时自动备份 |
| `backup_时间戳/` 目录 | 管理员执行「数据备份」时创建，包含 `data/` 目录所有文件的副本 |
| `export_用户名.txt` | 用户执行「导出数据」时创建，为明文文本（默认文件名，可自定义） |

> `backup_时间戳/` 目录中的文件为加密格式（与 `data/` 中一致）；`export_用户名.txt` 为**明文**，包含密码信息，请妥善保管。
