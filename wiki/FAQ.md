# 常见问题

## 中文乱码

### 症状

程序运行后中文显示为乱码（如 `锘?` 或 `???`）。

### 原因

Windows 控制台默认使用 GBK 编码，而源文件使用 UTF-8 编码。

### 解决方案

程序已在 `main.cpp` 中设置控制台编码：

```cpp
SetConsoleOutputCP(65001);  // 设置输出为 UTF-8
SetConsoleCP(65001);        // 设置输入为 UTF-8
setlocale(LC_ALL, "Chinese_People's Republic of China.utf8");
```

编译时必须添加 `-finput-charset=UTF-8` 参数：

```bash
g++ -std=c++11 -finput-charset=UTF-8 -Iinclude ...
```

如果仍然乱码，检查源文件是否确实以 UTF-8 编码保存。

## 登录失败

### 症状

使用正确的用户名和密码无法登录，或管理员用户列表为空。

### 可能原因与解决

**原因 1：使用了旧版转换工具导致数据损坏**

旧版 `convert.exe` 独立实现加密算法，可能与主程序不一致。

解决：
1. 恢复 `.bak` 备份文件（去掉 `.bak` 后缀覆盖 `.dat`）
2. 运行新版 `password_manager.exe`，数据会自动升级
3. 或运行新版 `convert.exe` 重新转换

**原因 2：users.dat 被覆盖为只含 Admin 的新文件**

如果主程序启动时 `users.dat` 解密失败返回空，会自动创建只含 Admin 的新文件，覆盖原有用户数据。

解决：
1. 检查 `data/` 目录下是否有 `.bak` 备份
2. 如有，恢复备份
3. 如无，需重新注册用户

**原因 3：管理员密码已被修改**

如果之前修改过管理员密码，初始密码 `admin_root` 将不再有效。

解决：
1. 使用修改后的密码登录
2. 如忘记密码，需手动删除 `data/users.dat`，重新运行程序会自动创建默认管理员

## 转换后无法登录

### 症状

运行 `convert.exe` 转换数据后，使用原有账号密码无法登录。

### 根因

转换工具和主程序的加密算法实现不一致（旧版转换工具独立实现了一套 XTEA 代码）。

### 解决方案

**方案 A：恢复备份 + 自动升级（推荐）**

```bash
# 1. 进入 data 目录
cd data

# 2. 恢复所有备份
# 将 .dat.bak 重命名为 .dat（覆盖损坏的文件）

# 3. 重新编译新版程序
cd ..
make clean
make

# 4. 直接运行主程序，旧数据会自动升级
password_manager.exe
```

**方案 B：使用新版转换工具**

```bash
# 新版 convert.exe 直接链接 crypto.cpp，与主程序共享加密实现
make convert
convert.exe
```

**验证**：

```bash
make runtest
# 40 项全通过则说明加密实现正确
```

## 密码输入显示为 `*` 但无法退格

### 症状

输入密码时按退格键无法删除字符。

### 原因

`getHiddenInput()` 只处理 `\b`（ASCII 8）作为退格。某些终端模拟器可能发送不同的退格码。

### 解决

确保在标准 Windows 控制台（cmd.exe 或 PowerShell）中运行程序。

---

## 数据文件被误删

### 症状

`data/` 目录下的 `.dat` 文件被删除，用户数据丢失。

### 解决

- 如果 `.bak` 备份文件存在，重命名恢复
- 如果没有备份，数据无法恢复，需重新注册用户并重新添加密码信息
- 管理员可以使用「初始化系统」功能清空并重置

## 程序闪退

### 症状

双击运行 `password_manager.exe` 后窗口一闪而过。

### 原因

程序可能在非交互环境下运行，或缺少 `data/` 目录创建权限。

### 解决

1. 在命令行中运行（不要双击）：
   ```bash
   cmd.exe
   cd 到程序目录
   password_manager.exe
   ```
2. 确保程序对当前目录有写入权限（需要创建 `data/` 目录）
3. 查看错误输出信息

## 修改了 XTEA_KEY 后无法解密旧数据

### 症状

修改 `types.h` 中的 `XTEA_KEY` 重新编译后，已有的新版格式数据无法解密。

### 原因

XTEA 是对称加密，解密必须使用与加密相同的密钥。

### 解决

1. 用旧密钥编译的程序读取并解密所有数据
2. 用新密钥编译的程序重新加密
3. 或使用转换工具（也需要用新密钥编译）

> **建议**：在首次部署时就确定好密钥，后续不要轻易修改。

## 同一明文每次加密结果不同

### 症状

相同的用户数据，每次保存后 `.dat` 文件内容不同。

### 原因

这是**正常行为**。新版加密使用随机 IV（初始化向量），每次加密的 IV 不同，因此密文也不同。这是 CBC 模式的安全特性，防止模式分析攻击。

### 验证

虽然密文不同，但解密后的明文是一致的。可以运行 `crypto_test.exe` 验证。

## 如何备份数据

### 方法一：使用内置「数据备份」功能（推荐）

以管理员身份登录，在管理员菜单选择「7、数据备份」，系统会自动将 `data/` 目录下的所有文件复制到 `backup_时间戳` 目录（创建在程序同级目录）。备份文件为加密格式，与原始数据一致。

### 方法二：手动复制 `data/` 目录

直接复制整个 `data/` 目录到安全位置：

```bash
xcopy /E /I /Y data data_backup
```

### 恢复

- **内置恢复**：以管理员身份登录，选择「8、数据恢复」，输入备份目录路径（如 `backup_2026_08_06_14_30_25`），确认后即可将备份数据覆盖回 `data/` 目录。
- **手动恢复**：将备份目录重命名回 `data/` 即可。

> `data/` 目录已被 `.gitignore` 排除，不会上传到 GitHub。

## 随机密码按 R 没有生成

### 症状

在添加信息 / 编辑密码 / 修改密码时输入 `R`，提示符没有出现随机密码。

### 原因与解决

- 隐藏输入函数会将输入的字符显示为 `*`，输入 `R` 后**回车确认**才会触发生成（不是按键即触发）。
- 正确操作：在密码输入环节输入 `R` 或 `r`，然后按回车，即可生成 16 位随机密码。
- 随机密码生成器（菜单第 9 项）中的 `R` 是按键触发，可直接重新生成，无需回车。

## 剪贴板复制失败

### 症状

查询 / 搜索详情页按 `C` 后提示「复制失败！」。

### 原因与解决

- `copyToClipboard()` 依赖 Windows 剪贴板 API（`OpenClipboard` / `SetClipboardData`），若剪贴板被其他程序独占会失败。关闭占用剪贴板的程序后重试即可。
- 复制成功后剪贴板内容为**明文密码**，请尽快粘贴使用，避免长时间留在剪贴板中。

## 密码强度是怎么判定的

### 规则

`checkPasswordStrength()` 基于密码长度和字符类型数量判定：

| 等级 | 条件 | 描述 |
|------|------|------|
| 0 | 长度 < 6 | 弱 |
| 1 | 长度 ≥ 6 且字符类型 ≥ 2 | 中 |
| 2 | 长度 ≥ 10 且字符类型 ≥ 3 | 强 |
| 3 | 长度 ≥ 12 且字符类型 ≥ 3 | 非常强 |

字符类型分四类：大写字母、小写字母、数字、特殊字符。强度仅作参考，并非绝对安全标准。

---

## 随机密码生成器支持的长度

- 范围 8-64 位，默认 16 位。
- 输入小于 8 会被视为 8，大于 64 会被视为 64。
- 生成的密码保证至少包含大写字母、小写字母、数字、特殊字符各一个（字符集 `!@#$%^&*_-+=`）。

## 导出的文件是明文吗

是的。「导出数据」生成的 `export_用户名.txt` 为**明文文本**，包含所有平台账号、密码、备注和创建时间。

### 安全建议

- 导出后尽快使用、尽快删除
- 不要将导出文件上传到云端或代码仓库
- 不要通过不安全的渠道（如聊天工具）传输

---

## 数据恢复会覆盖现有数据吗

会。「数据恢复」会将备份目录中的所有文件复制回 `data/` 目录，**覆盖**当前数据，且恢复前需输入 `Y` 二次确认。

> 建议在恢复前先执行一次「数据备份」，保留当前数据的副本，避免误覆盖。

---

## 旧数据没有备注和创建时间

### 症状

升级到新版后，原有平台信息没有显示备注和创建时间。

### 原因

旧版本数据行格式为 `平台名:账号列表:密码`（不含 `\t` 字段），没有备注和创建时间信息。

### 解决

这是正常现象。读取旧格式数据时，备注和创建时间字段为空。新添加的平台信息会自动记录创建时间。旧数据可在「编辑信息 → 编辑备注」中手动补充备注。

> 旧格式数据被读取并以新格式（带 `\t`）重新写入后即完成升级，向后兼容。
